# 논리 필터·QB/OQB 선언 확장 검토안

**상태: 설계 전용 — AWAITING OWNER GO/NO-GO. 이 문서는 구현 승인이 아닙니다.**

검토 기준: RFC3 부등호 정렬과 명시적 RFC2 이관이 반영되는 0.2.0 후보. 여기서 제안하는 OR/NOT·개수·부분 범위·등장 차수·관측 분기 확장은 이번 코드에 추가하지 않습니다. 기존 `reference`, `select`, `before`, `present`, AND 선언은 이미 있는 기능이며, 아래의 확장형 의미와 동일하지 않습니다.

## 1. 목적과 변경하지 않을 경계

새 단축 문법의 이유는 Clearra의 큐/패턴 입력과 내부 구조에 가까운 명시적 범위를 제공하기 위해서입니다. Marfung/Sfinder가 부족해서 새 형식이 불가피하다는 주장은 하지 않습니다. 문법상의 집합·범위·관계가 내부 데이터와 자연스럽게 대응하도록 만드는 것이 기준입니다. KPCA가 정확한 이름이며 앞서 KPCO는 오타였습니다.

형식의 의미 범위는 확장할 수 있지만 실행 책임은 늘리지 않습니다. 자연어 처리·LM 사용/학습, PC 탐색, 해법 점수/탐색 우선순위, QB/OQB 정책 합성, 외부 데이터셋 다운로드·조회·캐시, Clearra/CTK3/Sfinder/Fumen/HF 어댑터 구현, 실제 가방 생성, 리플레이 실행은 제외합니다. 사용자가 지정한 외부 명령이나 참조를 자동 실행하지 않습니다. MIT, npm 실행 의존성 0개, Rust 포맷 크레이트와 선택적 개발 도구의 분리를 유지합니다.

## 2. 승인 단위

| 단위 | 제안 | 권장 결정 | 현재 |
|---|---|---|---|

| F2 | 부분 범위·등장 차수 선택자 | F1 이후 별도 GO | 미승인·미구현 |
| Q1 | QB/OQB의 관측·결정·목표·공통 진행 참조 | GO 후보 | 미승인·미구현 |
| M1 | 외부 정책 자료의 리비전·상태·그래프·결과 단위 계약 | Q1의 선택적 부분 | 미승인·미구현 |

## 3. F1 — 논리 필터의 내부 형식과 사용자 문법

### 3.1 내부 모델

제안 AST는 `All`, `Any`, `Not`, `Before`, `Present`, `Count`입니다. 이것은 이번에 추가하는 코드 심벌이 아니라 검토용 모델 이름입니다. 쉼표와 미노 그룹의 AND, 최초 등장·부재 규칙은 그대로 유지합니다. 내부 Before(A,B)는 언제나 A 선행이며 표면 부등호의 방향은 의미 프로필로 고정합니다.

관계 종류를 플러그인/확장 태그로 분리합니다. 기본 독자는 익숙한 Before/Present만 구현할 수 있고, 모르는 필수 의미는 `UNSUPPORTED`로 보고해야 합니다. 모르는 조건을 버리고 큐를 넓히면 안 됩니다. 단순 코드 검사만으로 모든 식의 만족 가능성을 풀지는 않습니다.

### 3.2 검토할 단축 구문

아래는 **제안 문법, 현재 파서에서 거부되어야 하는 예시**입니다.

```text
P7:D(I<T | S<Z)
P7:D(!(I<T))
P4:D(T=1)
P4:D(T=0)
P7:D((I<T | S<Z), T)
```

권장안은 콤마=AND, `|`=OR, `!`=NOT, 괄호=명시적 묶음입니다. 공급 본문의 `!`(전체 순열)와 `[]`(미노 풀), `;`(공급 대안)는 그대로 둡니다. `&&`/`||`를 별도 별칭으로 동시에 제공하는 것은 첫 버전에서는 보류합니다. 논리 필터 안의 대괄호에 OR 의미를 다시 부여하지 않습니다.

결합 우선순위는 선택자/개수/선후 원자 → `!` → 쉼표 AND → `|` OR를 권장합니다. 파서는 실제 구문 트리를 출력할 수 있어야 하고, 출력기는 혼동 가능한 AND/OR 결합을 괄호로 표시합니다. 예를 들어 `I<T | S<Z,T`는 `I<T | (S<Z AND T 존재)`이며 `(I<T | S<Z),T`와 다릅니다.

개수 조건의 숫자는 비교 위치가 아니라 해당 범위의 종류별 출현 횟수입니다. `TS=1`을 허용한다면 T가 정확히 1개 AND S가 정확히 1개로 정의해야 하며 합계 1개나 OR로 해석하지 않습니다. 초기 F1에서는 단일 종류의 개수 비교만 노출하고, 다중 종류는 `T=1,S=1`처럼 명시하는 안을 권장합니다. 연산은 `=`, `!=`, `<`, `<=`, `>`, `>=`, 정수 범위는 유한 문서 한도 내입니다. 숫자 부등호는 선후 비교가 아닌 일반적인 수량 비교입니다.

### 3.3 중요한 논리 예외

`!(I<T)`는 `T<I`와 같지 않습니다. I·T가 둘 다 없는 범위에서는 전자가 참, 후자가 거짓입니다. 관측되지 않은 미래를 부재로 바꾸지도 않습니다. 공급의 완성된 범위에 대한 논리 평가와 관측 정보로 확정할 수 있는지의 판정은 다른 계층입니다.

같은 범위와 D/U 영역의 순환은 해당 AND 가지를 UNSAT로 만들 수 있습니다. OR 가지 하나가 불가능하다고 전체 OR를 불가능으로 만들면 안 됩니다. NOT 아래의 식은 긍정 조건처럼 순환 그래프에 합치지 않습니다. 정확한 증명을 못하면 NOT_CHECKED, 처리 한도는 INCOMPLETE이며, 빈 성공·UNSAT로 바꾸지 않습니다.

임의의 모든 OR/NOT 식을 DNF/CNF로 전개하지 않습니다. 지수적 증가 없이 AST를 보존하고 노드·관계·깊이의 공유 예산을 적용합니다. 단순 평가기는 한 완성 큐/사용 증거의 조건 검사까지만 수행하고 큐 탐색/정책 최적화는 호스트가 담당합니다.

## 4. F2 — 부분 범위와 등장 차수

### 부분 범위

현재 `{}`는 공급 표현을 묶고 가방을 새로 만들지 않습니다. F2는 이미 선택된 범위의 하위 구간을 가리키는 내부 `Window(start,end)`를 추가하는 안입니다. 정본은 0부터 시작하며 끝 제외 `[start,end)`로 제안합니다. UI가 1-based 표시를 사용한다면 변환을 명시하고 같은 저장 필드를 혼용하지 않습니다. 범위를 벗어나면 자동 자르기가 아닌 명시적 오류를 권장합니다. 선택된 길이가 미정이면 호스트 요구 또는 미확정으로 남깁니다.

범위 연산을 가방 번호로 바꾸지 않습니다. 가방 참조가 필요하면 생성 정책/커서/출처로 확인된 가방만 사용합니다. 서로 다른 가방이 한 `{}`에 있어도 유효하며, 어떤 T를 참조하는지 선택자가 명시해야 합니다.

### 등장 차수

기본 `I<T`는 그대로 최초 등장입니다. 고급 내부 선택자는 `Occurrence(kind,n,scope)`이며 n은 1부터 시작합니다. `TT<I`를 기본 그룹에서 조용히 ‘두 번째 T’로 바꾸는 것은 금지합니다. 필요할 경우 `AT(T,2)` 같은 대문자 고급 구문을 후속 검토하되 F1에는 넣지 않습니다.

두 번째로 공급되는 T의 위치와, 홀드에 보관한 특정 출처의 T는 별개입니다. D의 발생 순서와 U의 실제 사용/출처 번호를 혼동하지 않습니다. 개별 출처에 대한 조건은 외부 호스트의 출처 대응 계약이 필요합니다. 일반 사용자가 같은 종류의 개체 번호를 매번 지정하도록 하지 않습니다.

## 5. Marfung/Sfinder와의 변환 계약

어댑터 구현은 외부 개발자의 책임입니다. 이 계획이 제공할 것은 변환 규칙·지원 가능 부분·거부 사례와 시험 자료입니다. Python 실행 의존성이나 Marfung 원본 코드를 npm 런타임에 넣지 않습니다.

| Marfung | 의미 보존 시 필요한 처리 |
|---|---|
| `*p7{I<T}` | `P7:D(I<T)`로 대응 가능 |
| `T[^T]!{I<O}` | `{T[^T]!}:D(I<O)`처럼 누적 범위를 보존 |
| 쉼표로 필터 범위를 다시 시작 | 단순 쉼표 삭제가 아니라 범위 노드로 변환 |
| `[TTI]!` | 중복 개수 보존, 테섬블리 단축 `[TI]!`로 축소 금지 |
| 필터의 `[TS]` OR | Any 노드로 변환; 공급 풀의 []와 구별 |
| `TT<I` | 등장 차수 확장이 없으면 변환 불가 |
| `1-3:` | 0-based 끝 제외 범위로 정확하게 변환 |
| `/regex/` | 초기 지원 범위 제외, 조용한 삭제 금지 |

기존 Sfinder/Marfung 표현을 읽는 도구가 필요할 때 외부 어댑터가 공급을 전수 열거할 수는 있지만, 예산 초과 시 INCOMPLETE를 반환해야 합니다. 부분 집합을 원래 전체 공급인 것처럼 내보내서는 안 됩니다.

## 6. Q1 — QB/OQB는 실행 스크립트가 아닌 정보·결정 선언

이미 있는 `select("setup",at=[0,2],choices=["A"])`는 시점/대상 참조의 기본 자료일 뿐, QB/OQB의 모든 의미가 구현된 것은 아닙니다. 현재 동작을 재명명하여 완성된 QB/OQB 기능으로 광고하지 않습니다.

### 제안 필드

| 필드 축 | 선언할 내용 |
|---|---|
| 선택 대상 | 셋업 변형, 종료 분기, 남길 재고 중 무엇을 확정하는가 |
| 기준점 | 셋업 시작, 스폰 완료, lock 수와 공개 이벤트의 관계 |
| 지식 조건 | 관측 이력, 현재/홀드/넥스트, 공개 규칙과 후보 관계 |
| 시점 | 시작 시 1회 또는 진행 후 추가 분기 가능 시점 |
| 공통 진행 참조 | 추가 관측 전까지 필요한 행동 자료의 외부 참조 |
| 목표 참조 | 이번 PC·잔여 미노·장기 기대 PC 수 등 외부 목표의 의미 |
| 연결된 선택지 | 버전 고정된 CTK3 등 자료의 식별자 |

QB는 지정된 시작 정보로 선택 대상을 확정하는 프리셋입니다. OQB는 허용된 공통 진행 후 새 정보로 선택을 구체화하는 프리셋입니다. ‘OQB=항상 1~2개 놓은 뒤’로 고정하지 않습니다. KPCA/PC INFO KOREA의 3p/4p 사례처럼 목표가 현재 성공률 개선이 아닌 세이브 선택일 수도 있습니다.

`at=[0,2]` 같은 기존 정수는 해석한 상태 전이의 phase를 기록하지 못하므로 새 확장에서는 기준점+배치 수+스폰/공개 전후를 명시합니다. 기존 키에 새 의미를 덮어쓰지 않고 새 선언 버전/확장 ID로 연결해야 합니다.

### 반드시 지킬 의미

관측 조건은 공급을 바꾸는 필터가 아닙니다. 보이지 않는 큐를 유리하게 다시 생성하거나, 관측되지 않은 미노를 없는 것으로 처리하지 않습니다. 다음 두 개가 SZ 또는 ZS라는 연결된 지식은 독립적인 [SZ][SZ] 후보로 풀지 않습니다. 같은 관측 이력에서 같은 선택을 해야 한다는 비예견성 조건은 계약으로 기록하되, 실제 정책 검증은 호스트가 담당합니다.

선택 시점을 추가해도 이미 둔 배치를 취소하지 않습니다. 공통 진행의 실제 합법성·모든 허용 공급에서의 성립·최적 대응·100% 성공은 외부 탐색기/검증기의 주장입니다. 테섬블리는 형식 유효성만으로 이를 증명하지 않습니다. ‘추가 관측 허용’, ‘실제로 사용’, ‘없으면 불가능’은 다른 결과 필드입니다.

홀드 NONE/EMPTY/OCCUPIED와 used_this_turn·종류별 금지 규칙은 계속 구별합니다. 현재 미노/홀드 쌍을 정렬해 합치는 것은 외부 엔진이 동등성을 보장할 때만 가능한 투영입니다. 실제 상태의 출처·잠금·공개량을 지우지 않습니다. 빈 홀드를 미노가 든 홀드로 변환하는 것도 공짜 선택권이나 추가 넥스트를 만들지 않는 외부 매핑이 검증된 경우에 한합니다.

## 7. M1 — 외부 자료·결과 의미의 보존

muse918의 상태/정책/그래프 표현을 범용 기본 구조로 채택하지 않습니다. 형식에는 provider, dataset revision, graph identity, state-index identity, rule/view/hold assumptions, result metric, action encoding, coverage를 기록할 수 있는 선택적 참조 계약을 제안합니다. 원본 자료를 내려받거나 색인을 조회하지 않습니다.

V*의 장기 기대 PC 개수는 이번 PC 성공 확률이 아닙니다. 자료가 반환한 수치의 단위·목표를 기록하되 테섬블리에 점수 함수나 최적화기를 추가하지 않습니다. 상태마다 기록된 추천 행동 하나와 가능한 모든 행동 집합도 구분합니다.

상태 미지원, 자료에 없음, 기록된 행동 없음, 인덱스/리비전 불일치, 입력 조건 모순은 서로 다른 상태입니다. DB 조회 실패를 UNSAT나 PC 불가능으로 변환하지 않습니다. 가방 잔여 마스크는 어느 커서 뒤의 잔여분인지와 함께 저장합니다. 공개된 꼬리 뒤의 마스크를 현재 미노 뒤의 잔여분으로 재해석하면 안 됩니다.

## 8. 구현 GO 이후의 작업물과 수용 기준

| 작업물 | 범위 |
